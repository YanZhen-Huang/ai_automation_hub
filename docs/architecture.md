# 架构与功能分化

## 1. 总体架构

```
             ┌──────────────────────────────────────┐
             │             desktop/ (tkinter)       │  托盘/窗口/设置
             │             server/ (FastAPI+Vue)    │  Web 界面/API/WS
             └──────────────────┬───────────────────┘
                                │ 事件
                ┌───────────────▼────────────────┐
                │         core/ (事件总线/调度)     │  模块解耦、定时触发
                └───────────────┬────────────────┘
        ┌──────────────┬────────┴───────┬─────────────────┐
        ▼              ▼                ▼                 ▼
  collectors/      ai/            automation/        storage/
   采集各来源      LLM提炼/决策      动作执行           SQLite/JSON
```

- **core**：事件总线解耦各模块；调度器按策略触发采集/执行/提醒。
- **collectors → ai → automation**：一条管线（采集 → 提炼 → 决策 → 动作），工作流固定。
- **desktop / server**：同一份数据、同一套事件，双端展示与操作。

## 2. 模块与功能分化清单

> 优先级：P0 阶段1必需 · P1 阶段2 · P2 阶段3

### core/ 底座
| 模块 | 功能 | 优先级 |
|------|------|--------|
| events.py | 事件总线（发布/订阅、跨线程安全） | P0 |
| config.py | 配置中心（JSON + 环境变量 + 热更新） | P0 |
| logger.py | 日志（滚动文件 + 控制台） | P0 |
| scheduler.py | 调度器（周期/定点/一次性任务） | P0 |

### collectors/ 采集
| 模块 | 功能 | 优先级 |
|------|------|--------|
| base.py | 采集源基类 + 注册表 | P0 |
| im/wechat | 微信会话采集（UIA 只读，复用经验） | P0 |
| im/dingtalk / feishu | 钉钉/飞书会话采集 | P1 |
| web/ | RSS、网页正文、接口轮询 | P1 |
| files/ | 目录/文件监听（新增/修改） | P1 |
| manual/ | **手动输入**（界面录入 / 文件导入） | P0 |
| speech/ | **录音转文字**（语音→文本，本地或 API） | P1 |

### ai/ 智能
| 模块 | 功能 | 优先级 |
|------|------|--------|
| llm/ | 模型接入（OpenAI 兼容、可切换多模型） | P0 |
| extract/ | 信息提炼（消息→结构化任务/要点） | P0 |
| decisions/ | 规则 + 阈值决策（无 Key 降级） | P1 |
| agents/ | 智能体（规划/工具调用/多步任务） | P2 |

### desktop/ 桌面端
| 模块 | 功能 | 优先级 |
|------|------|--------|
| tray.py | 系统托盘 | P0 |
| windows/main | 工作台主窗口（任务/来源/日志/执行记录） | P0 |
| windows/settings | 设置（Key/来源/策略） | P0 |
| windows/* | 详情、执行日志等子窗口 | P1 |

### server/ Web 端
| 模块 | 功能 | 优先级 |
|------|------|--------|
| api/ | FastAPI 路由（任务/来源/执行/设置） | P0 |
| frontend/ | Vue(CDN) 单页 + 静态资源 | P1 |
| ws.py | WebSocket 实时推送 | P1 |

### automation/ 执行
| 模块 | 功能 | 优先级 |
|------|------|--------|
| actions.py | **动作库（重点）**：发消息/开程序/运行脚本/写文件/发通知等 | P0 |
| workflows.py | 固定工作流：采集→提炼→动作 的固定管线（复杂编排暂缓，待详谈） | P1 |

### storage/ 存储
| 模块 | 功能 | 优先级 |
|------|------|--------|
| db.py | SQLite 访问层（任务/来源/执行记录/设置） | P0 |
| migrations.py | 表结构迁移 | P1 |

## 3. 阶段 1 最小闭环（P0）

```
信息接入(微信自动 + 手动输入) → LLM 提炼任务 → 事件总线 → 存储(SQLite)
            → 桌面实况窗/托盘 + Web 列表 → 执行动作(动作库) → 记录
```

## 4. 已完成（阶段1 桌面端 + Web + 手机联动）

- **core**：事件总线 / 调度器 / 配置中心 / 日志 ✅
- **storage**：SQLite 双库（信息库 info_items + 会议库 meetings/prep_items/action_logs/phone_numbers）✅
- **collectors**：微信 UIA 采集 / 手动输入 / 录音转文字（faster-whisper，未装则关闭）✅
- **ai**：LLM 接入（DeepSeek/OpenAI 兼容）+ 信息提炼（AI + 规则降级）✅
- **automation**：固定工作流（一阶段并行 8 项 / 二阶段串行 4 项）、动作库（通知/导出/PPT/微信/电话）、手机联动 HTTP ✅
- **desktop**：托盘 + 主窗口（会议/信息/日志/号码配置）✅
- **server**：FastAPI + Vue(CDN) 前端（可操作）✅
- **phone_app**：鸿蒙 ArkTS 工程骨架（拉取任务/拨打/TTS 播报/录音转文字回传）✅（真机联调待 DevEco）

## 5. 端口与通信
- Web 端：`127.0.0.1:8780`
- 手机联动：`0.0.0.0:8781`（手机局域网访问）
  - `GET /phone/poll` 拉任务 · `POST /phone/result` 回传
- 号码配置：桌面端「手机联动号码」页 / `GET|PUT /api/phone-numbers`
