# 工程概况 · 给下一个 AI 的上手说明

> 目的：让**任何接手本项目的 AI/开发者**在 5 分钟内看懂「这是什么、为什么、已做到哪、怎么改」。详细技术实现见 `FULL_ANALYSIS.md`，使用说明见 `guide.md`。

---

## 1. 这是什么

**会议准备自动化工作台**：一个 Windows 桌面 + Web 双端 + 鸿蒙手机联动的**会议前准备自动化系统**。

一句话业务：**收集开会相关信息 → AI 提炼 → 按固定流程自动筹备一场会议**（订会议室、安排茶水/服务/音响、AI 写汇报材料转 PPT 并交付印刷、微信下通知、定签字表、排桌牌、提醒接待），其中"打电话"环节由鸿蒙手机 App 自动拨打 + 语音播报 + 录音转文字回传。

## 2. 为什么做（用户核心诉求）

用户是行政/会务角色，会前有大量重复、并行的事务性电话与材料工作。本系统把它们做成**固定工作流**，让 AI 承担信息提炼、材料生成、话术组织，让手机自动打电话，让人只做**必须人做的决策**（选会议室、定人员、审批、确认）。

**关键原则（改代码前必读）**：
- 固定工作流 = 一阶段并行 + 二阶段串行（不是通用编排引擎，别复杂化）
- 一切自动化动作执行前**必须人工审批**
- 打电话动作由**鸿蒙手机端**完成，桌面端只负责生成话术 + 目标号码
- 所有关键配置（AI Key、端口、OCR、微信、话术模板、号码、会议室）都可在设置里改
- 系统要能"降级可用"：无 AI Key → 规则；无微信 → 生成文本；手机不在线 → 超时重试、不卡死

## 4. 技术栈一句话

Python 3.13：tkinter + pystray（桌面）｜ FastAPI + uvicorn + Vue3 本地（Web）｜ SQLite(WAL)（存储）｜ DeepSeek/OpenAI 兼容（AI，可降级规则）｜ uiautomation（微信）｜ RapidOCR（屏幕识别）｜ python-pptx（PPT）｜ 鸿蒙 ArkTS（手机）

## 5. 核心架构速览

```
信息采集(微信/手动/OCR/录音) → 去重入库(info_items)
        → AI 提炼 → 创建会议 → 12 个动作项(一阶段并行+二阶段串行)
        → 每动作先"待审批" → 审批后执行
        → 打电话类: 桌面生成话术 → 手机 HTTP 拉取 → 拨打+播报+录音回传 → 动作完成
        → 二阶段串行推进，全程桌面/Web 实时显示
```

三个运行时服务（都在主程序内）：
- Web 服务：127.0.0.1:8780
- 手机联动：0.0.0.0:8781（token 鉴权）
- 调度器：15s 轮询，按配置间隔节流采集/OCR

```powershell
# 浏览器 http://127.0.0.1:8780
```

验证链路（改完必须回归）：
1. 创建会议 → 12 动作项进入待审批
2. 选会议室 → 生成话术含房间 → 提交手机任务
3. 定人员 → 桌牌话术含名单
4. 审批材料 → 生成 PPT + 微信发文件 + 印刷话术（含送达地点）
5. 手机回传确认 → 动作 done → 二阶段串行推进
6. 打包版：OCR 能识别、token 401 拦截、PPT 生成

## 7. 改代码前必读约定

- **不要**把固定工作流改复杂（用户明确"工作流固定，重点在动作"）
- **不要**移除审批；所有自动化动作先 waiting 再 approve
- **不要**跨线程调 tkinter：事件必须经 `queue.Queue`（desktop `_post`/`_drain_ui`）
- **不要**让电话任务无限卡在 running：手机回传/超时/失败都要落到 `waiting` 可重试
- 材料生成**只取本会议信息**，禁止 `or db.list_info_items()` 全库回退（会串会）
- 文件名/时间/外部输入必须校验清洗（`actions.sanitize_filename`）
- 新增设置项 → 加入 `core/settings.py` 白名单，桌面/Web 自动渲染
- 新增动作 → 在 `workflows.py` 定义 code，`actions.py` 实现，`phrases.py` 配话术
- 改配置/新增接口后：桌面/Web 端 + 文档一起同步
